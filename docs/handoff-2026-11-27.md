**Sign-in → desktop handoff: root cause found and fixed in `2e318ec`, not yet verified on the laptop.**

- Laptop run on build `e9d3f95`: Connect on the locked BeaconTest → password prompt live in ~14 s → password typed
  through the viewer → Windows signed in → handoff refused: `no desktop handoff: acknowledged false (input released
false, Disable window closed true)`, viewer ended on "Sign-in connection ended".
- Cause: the worker marked video "done" only after the video thread dropped its **hardware Media Foundation encoder +
  `MFShutdown`** (over a second). `peer()` waits only 500 ms for that thread, so `Completion::complete()` was false and
  retirement always said "cleanup not confirmed". The log never showed "video thread ended", which is the giveaway.
- Fix (`apps/windows-agent/src/signin_media.rs`): `video()` now stops the scope, drops capture and the packet queue,
  stores `completion.video = true`, then drops the encoder (logs `video: capture released` and `video: encoder
released after N ms`). `stop_and_cleanup` logs `media cleanup: joined …, input released …, video stopped …`.
  "media runner started" is no longer logged on every renewal.
- Viewer fallback (`SignInView.tsx`, `signin-handoff.ts` `signedIn`/`desktopAfterSignIn`, `main.tsx` `onSignedIn`): if
  the handoff still fails but the computer reports `signed-in`, the view keeps its last picture and opens the
  ordinary trusted desktop session, retrying for 45 s while the desktop host comes online (stops at once on 401/403).
- Checks run: web typecheck, handoff tests (6 pass), agent clippy clean, agent sign-in tests (80 pass).

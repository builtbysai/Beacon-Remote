  Computer in the lab workspace: **SURFIENA-TEST** `76d6891d-a4f2-4606-bfd0-944eec496300`, trusted view+control, boot
  and sign-in services installed. Never type the owner's PIN.
- **Link.** Direct cable 10.77.0.1 (PC, "Ethernet 2") ↔ 10.77.0.2. After a reconnect the adapter can reset a few times;
  wait for `Get-NetAdapter 'Ethernet 2'` to say Up. SSH: `ssh beacon-surfiena-link` (cable; Tailscale SSH is blocked by
  design). The SSH login is an **elevated administrator**, so services can be installed/repaired without UAC.
- **Backend.** Lab fixture: `$env:LAB_SCHEMA='lab_dev_934cb4410046418bae7b8e3d64932e9d'; pnpm --filter
  @beacon-remote/backend exec tsx scripts/lab-development.ts` (after `. ./scripts/Enter-Workspace.ps1`), backend 3012,
  web 5176, Postgres in Docker on 5433. Restart it after backend code changes.
- **Tunnel** (re-create after any disconnect):
  `ssh -o ExitOnForwardFailure=yes -o ServerAliveInterval=15 -N -R 127.0.0.1:3012:127.0.0.1:3012 beacon-surfiena-link`.
- **Lab helpers** drive each profile's screen: `node scripts/lab/lab.mjs …` for the owner's session, and with
  `LAB_REMOTE_ROOT=C:/Users/BeaconTest/BeaconLab` for BeaconTest (scheduled task `BeaconLabAgent-BeaconTest`, starts at
  its logon). Windows refuses the foreground to a background helper when nothing has focus, so prefer the agent CLI
  (`pair`, `access trusted --control`, `unattended-finish`) over clicking windows. Lock a profile without input:
  `lab.mjs launch C:/Windows/System32/rundll32.exe user32.dll,LockWorkStation`.
- **Deploy a build** (works while locked): `./scripts/Build-DevelopmentHost.ps1 -SignInMedia -RequireSigning` (commit
  first; never redirect its output, PowerShell 5.1 turns cargo's progress into an error), then from Git Bash
  `bash scripts/lab/deploy-lab.sh` (default profile BeaconTest; `LAB_PROFILE=saiha` for the owner). It installs
  silently, repairs the services over SSH (`Repair-LabSignIn.ps1`) and re-applies the cable-only media rules.
- **Why the cable rules matter.** Without them media may take the Tailscale path, which is throttled and loses most
  full-size packets (black video). The rules are per program path, and each Repair creates a new version folder, so
  `deploy-lab.sh` re-applies them every time.
- **Diagnostics.** Sign-in supervisor log `C:\ProgramData\BeaconRemoteSignIn\<machine>\supervisor.log` (+ `.old.log`).
  In the browser, inbound WebRTC stats (framesDecoded, packetsLost, selected pair) tell transport from decode problems.
